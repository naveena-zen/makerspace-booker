1. Git Branching & Review Workflow

Engineered around a dual-tier protection scheme: production main receives thoroughly vetted releases from staging develop, fed by isolated feature/* branches.

Pull Requests

All code enters via tracked Pull Requests with automated templates and context summaries, ensuring high transparency.

Branch Protection

Main and develop are locked against direct pushes. CI status checks and peer approval are non-negotiable gates.

Conventional Commits

Structured commit types (feat:, fix:, ci:, refactor:) enable semantic versioning and auto-generated changelogs.

Peer Code Review

Designated code owners review logic and safety checks prior to squash-and-merge into staging.

name: Continuous Integration
on:
  pull_request:
    branches: [develop, main]

jobs:
  validate:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        service: [monolith, gateway, machine-service, certification-service, reservation-service]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'
      - name: Install Dependencies
        run: npm ci
        working-directory: ${{ matrix.service }}
      - name: Code Quality (ESLint)
        run: npm run lint
        working-directory: ${{ matrix.service }}
      - name: Automated Tests (Jest)
        run: npm test
        working-directory: ${{ matrix.service }}
      - name: Build Container Image
        run: docker build -t maker-${{ matrix.service }}:test .
        working-directory: ${{ matrix.service }}

3. Monolith to Microservices Architecture

Stepwise migration decomposing monolithic Express code into four focused microservices with distinct domain boundaries and an API Gateway.

Dimension Monolith (Phase 1) Microservices (Phase 2) Architectural Benefit
Deployment Independence × Coupled All endpoints packaged in single image ✓ Autonomous Independent Docker containers Rapid pinpoint hotfixes without broad regression risk
Targeted Elasticity × Heavy Must scale entire process memory ✓ Granular Scale reservation-service independently Optimizes server compute costs by up to 60%
Fault Isolation × Cascading Single crash brings down all routes ✓ Resilient Failures stay isolated in containers Ensures high availability even under degraded catalog services
Team Ownership × High Contention Git merge conflicts in one repo ✓ Clear Boundaries Dedicated contracts & test suites Aligns software architecture with Conway's Law
